# EasyCode AI

Учебная платформа для 3–6 классов: теория, программирование блоками и текстовыми командами, виртуальная машина и кабинет учителя. Первый этап — локальная рабочая основа; подключение облачной базы, наполнение всей практикой и школьный пилот выполняются отдельно.

## Запуск

Нужен Node.js 24 LTS и npm.

```sh
npm install
cp .env.example .env
npm run dev
```

Если `.env` уже существует, не перезаписывайте его: добавьте только отсутствующие переменные из `.env.example`.

Откройте `http://localhost:5173`. API работает на `http://localhost:3001`; в разработке веб-приложение направляет запросы `/api` на него.

Главная `/` знакомит с платформой и показывает интерактивную демонстрацию. `/login` и `/register` открывают формы входа и регистрации; `/learn` — учебное пространство, `/learn?practice=1` — сразу практическую среду. Без аккаунта доступны локальный запуск машины и черновик в браузере. Для серверной проверки с сохранением результата и подсказок предлагается войти; гостевой режим не отправляет эти запросы.

Команда `npm run dev` запускает оба процесса через локальный `scripts/dev.mjs`; остановка — `Ctrl+C`.

При `DEMO_MODE=true` ключи не нужны. Можно проверить роли учителя и ученика, классы, задания и практику. Демо-данные находятся в памяти API и исчезают при его перезапуске. Режим предназначен только для локального компьютера; это не настоящая авторизация и не подключённая облачная база.

## Что входит в первую версию

- Каталог из шести разделов и двенадцати тем, веб-уроки и предоставленные учебные файлы.
- Отдельные страницы тем, шаги чтения, самопроверка и персональный прогресс.
- Публичная ознакомительная страница с демонстрацией, переходами к входу, регистрации и гостевой практике.
- Практика с машиной: Blockly, текстовый редактор и визуализация выполнения.
- Безопасный ограниченный Python-подобный язык вместо запуска произвольного кода.
- Повторная проверка решения на сервере общим движком.
- Создание учителем классов, разделов и заданий; присоединение ученика по коду.
- Схема Supabase, разделение ролей и серверная настройка AI-подсказок.

Работающий локальный сценарий не означает готовый полный курс. Всего планируется 18 упражнений; робот, электронные компоненты, свободный конструктор и подробная аналитика вынесены в [план реализации](docs/ROADMAP.md).

Форма учителя создаёт задание на подготовленном поле: название, описание и сложность задаются учителем, визуального редактора карты пока нет. API уже принимает собственные поля по контракту `world`. Загрузка и редактирование файлов в кабинете ещё не реализованы.

## Ключи и настройки

Значения добавляются самостоятельно в локальный `.env`. Он исключён из Git. В `.env.example` секретов нет.

| Переменная | Назначение |
| --- | --- |
| `DEMO_MODE` | `true` для локальной демонстрации; `false` для настоящих аккаунтов и базы |
| `HOST` | Локальный адрес API; для деморежима `127.0.0.1` |
| `PORT` | Порт API; по умолчанию `3001` |
| `FRONTEND_ORIGIN` | Разрешённый адрес сайта без пути; локально `http://localhost:5173`. Если API привязан к loopback, также разрешены `127.0.0.1` и `[::1]` с теми же протоколом и портом. Для публичного адреса разрешён только указанный origin. |
| `VITE_SUPABASE_URL` | Публичный URL проекта Supabase для браузера |
| `VITE_SUPABASE_ANON_KEY` | Публичный anon-ключ Supabase для браузера |
| `SUPABASE_URL` | URL того же проекта для API |
| `SUPABASE_SERVICE_ROLE_KEY` | Секретный сервисный ключ Supabase; только сервер |
| `OPENAI_API_KEY` | Секретный ключ OpenAI; только сервер, необязателен для обычной практики |
| `OPENAI_MODEL` | Идентификатор модели для AI-подсказок |

Ключи `OPENAI_API_KEY` и `SUPABASE_SERVICE_ROLE_KEY` нельзя помещать в переменные с префиксом `VITE_`, код клиента, документы или коммиты. Всё с префиксом `VITE_` потенциально доступно посетителю сайта. После изменения окружения перезапустите приложение.

Без ключа и модели OpenAI используются локальные учебные подсказки. Реальный запрос к модели может расходовать средства аккаунта; он включается только после самостоятельной настройки. Подсказка не определяет оценку задания.

## Подключение Supabase

1. Создайте или выберите проект Supabase.
2. Примените SQL-файлы из `supabase/migrations/` по порядку в SQL Editor выбранного проекта. Сначала проверьте миграции на отдельной тестовой базе, если в проекте уже есть данные.
3. Заполните переменные Supabase в `.env`, установите `DEMO_MODE=false` и перезапустите приложение.
4. Настройте адрес сайта и разрешённые адреса возврата в Supabase Auth. Для локальной разработки это адрес веб-интерфейса, не API.
5. Для выбора роли при новой регистрации примените [миграцию ролей](supabase/migrations/202610070002_signup_roles.sql) после предыдущих миграций. Она обновляет обработчик создания профиля, не меняя роли существующих пользователей. Без неё прежний обработчик создаёт всех пользователей учениками.
6. При регистрации выберите «Ученик» или «Учитель» и выполните предусмотренное настройками подтверждение почты. Серверный триггер один раз переносит допустимую выбранную роль в защищённый профиль. Неизвестная или отсутствующая роль становится `student`.
7. При входе выберите роль своего аккаунта. Она сверяется с сохранённым профилем, а не назначается заново. Успешный вход и последующее редактирование метаданных не переводят ученика в учителя.

Учитель создаёт только собственные классы и публикует в них уроки/разделы и задания; административных прав или доступа к чужим классам эта роль не даёт. Выбор роли учителя при регистрации открыт и не является проверкой работы в школе: зарегистрировавшийся учитель также получает доступ к общим учительским материалам курса.

Существующие аккаунты сохраняют прежнюю роль. Если ранее созданному аккаунту нужна другая роль, это отдельное согласованное административное изменение защищённого профиля; форма входа и `user_metadata` не являются способом такого изменения. SQL-миграции не применяются автоматически при запуске приложения.

Перед реальным использованием проверьте два разных класса: учитель не должен видеть чужой класс, ученик — чужие попытки и конспекты преподавателя. Подключение и ограничения доступа нельзя считать проверенными только по успешной локальной сборке.

## Учебные материалы

В `content/materials/` сохранены восемь оригиналов: план разделов, четыре презентации и три конспекта учителя. Каталог описывает доступную аудиторию. Ученикам выдаются презентации, а конспекты остаются учителю; неизвестные файловые пути API не выдаёт.

Основной формат обучения — страницы `/learn/topic/1.1` … `/learn/topic/6.2`. Четыре первых урока адаптированы из презентаций, тема 3.1 — из предоставленного конспекта. Семь недостающих тем дополнены новыми материалами. В каждом уроке четыре учебных шага, примеры, задание и три вопроса. Тема считается пройденной после отметки всех шагов и верных ответов на все вопросы. Это прогресс самопроверки, а не оценка практической работы или сертификат.

Примеры Scratch отделены от возможностей EasyCode. Презентации можно просматривать внутри сайта как подготовленные PDF-копии; исходные DOCX/PPTX остаются доступными для скачивания с прежними правами доступа. В Supabase-режиме файлы хранятся в приватном Storage, а API после проверки аккаунта и класса выдаёт ссылку на 60 секунд. Браузер получает файл напрямую из Storage без передачи ему заголовка авторизации платформы. В локальном деморежиме API по-прежнему читает файлы из `content/materials/`. Анимации PowerPoint в статичной PDF-копии не воспроизводятся. Учитель может загружать PDF, PPTX с PDF-копией и DOCX в свой класс. Состав источников: [каталог материалов](content/materials/README.md).

### Подключение Storage и загрузка учителем

Выполните **до деплоя этой версии**, используя тот же Supabase-проект, что указан в ENV:

1. Откройте Supabase → SQL Editor → New query, вставьте целиком
   [202610140001_material_storage.sql](supabase/migrations/202610140001_material_storage.sql)
   и нажмите Run. Нужны уже существующие `profiles`, `classes`, `sections`.
   Миграция создаёт отдельную таблицу `learning_materials`, не меняет старую
   таблицу `materials`, создаёт приватный bucket `easycode-materials` (20 МБ/файл).
   Прямой доступ браузерных ролей к bucket запрещён даже при старых широких RLS-политиках.
2. В локальном `.env` должны быть `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`
   целевого проекта. Не публикуйте их и не используйте `VITE_` для сервисного ключа.
3. В корне проекта выполните `npm run materials:check`, затем `npm run materials:upload`.
   Это перенесёт 16 исходных материалов и 12 PDF-копий в Storage, а названия,
   аудиторию и пути — в таблицу. Первая команда ничего в облаке не меняет.
   Повторный импорт переиспользует одинаковые файлы без перезаписи и обновляет
   записи встроенного курса по `course_key`; материалы учителей не затрагиваются.
   Локальные оригиналы не удаляются. Старые версии объектов остаются в Storage.
4. Отправьте код в Git и дождитесь нового деплоя. В кабинете учителя выберите
   класс → «Материалы класса» → «Загрузить материал». Укажите название, урок
   (либо общий материал), файл. PPTX требует отдельный PDF для просмотра;
   автоматическая конвертация PowerPoint не выполняется. DOCX только скачивается.

Презентацию также можно прикрепить сразу в форме «Новый урок»: выберите PDF
либо PPTX вместе с PDF-копией. После сохранения файл появляется в «Материалах
класса» с привязкой к созданному уроку. При ошибке загрузки урок остаётся
сохранённым, а повторная отправка открытой формы повторяет только загрузку,
не создавая ещё один урок. Можно закрыть форму и прикрепить файл позднее через
«Материалы класса». Поля и сообщения доступны на всех трёх языках.

Загрузка состоит из выдачи подписанного upload-токена на новый серверный путь,
прямой передачи файла в Storage и подтверждения публикации сервером. До проверки
размера и сигнатуры файл имеет статус `pending` и не виден ученикам. Ученик читает
только материалы своих классов, учитель — своих; роль берётся из серверного профиля.
Учебные оригиналы/PDF больше не включаются в Vercel Function, только `catalog.json`.
Интерфейс и проверки доступны на русском, казахском и английском.

Ограничения: не более 100 записей (включая незавершённые) на класс при обычной
последовательной загрузке; конкурентные запросы могут кратковременно превысить этот
порог. Неудачная загрузка может оставить `pending` и объекты: администратор очищает
их после истечения upload-ссылок (2 часа), предварительно проверив статус записи.
Автоматического удаления, редактирования файлов и антивирусной проверки пока нет.
Не удаляйте записи/объекты действующих материалов при очистке.

### Виртуальная электроника

Во вкладке «Практическая среда → Электроника» (`/learn?practice=1&environment=electronics`) доступны монтажное поле, перемещение деталей, соединение контактов проводами, удаление и отмена изменений. Компоненты: плата EasyBoard, резистор 220 Ом, светодиод, кнопка и модуль датчика света — по одному каждого типа.

Поддерживаются Blockly и ограниченный учебный Python: `led.on()`, `led.off()`, `wait(500)`, фиксированные циклы, условия `button.pressed()` и `sensor.dark()` с `else`. Программа повторяется, пока не остановлена; изменение входов начинает новый проход. Есть пошаговое выполнение и три локальных задания: мигание, кнопка и ночник. Проверка обнаруживает разрыв цепи, отсутствие резистора, неверную полярность и прямое короткое замыкание питания/выхода с землёй. Интерпретатор не использует eval и ограничивает длину кода, вложенность, действия и длительность прохода.

Это логическая учебная модель поддерживаемой цепи D9 → резистор → LED → GND, **не SPICE, не Arduino-эмулятор и не проверка безопасности реальной электроники**. D2 имеет идеализированную внутреннюю подтяжку к земле; модуль света требует VCC/GND/OUT. Ток, напряжения по узлам, нагрев, макетная плата, произвольные схемы и несколько одинаковых деталей пока не моделируются. Черновик схемы и программы сохраняется вручную в localStorage отдельно для каждого аккаунта. После входа «Проверить задание» отправляет код, блоки и схему на серверную проверку и сохраняет попытку для журнала учителя. Гостю доступна только локальная самопроверка. Произвольные задания учителя пока остаются заданиями для машины; в электронике проверяются три встроенных упражнения.

### Журнал учителя: прогресс, решения и оценки

Перед деплоем выполните [202610140002_teacher_review.sql](supabase/migrations/202610140002_teacher_review.sql)
в Supabase → SQL Editor. Нужны существующие `profiles`, `classes`, `class_members`,
`submissions`; для прогресса теории — ранее настроенная `lesson_progress`.
Миграция расширяет попытки машины снимком блоков, исходными условиями задания и
ссылкой на тему; добавляет `electronics_submissions` и `section_grades`.
Старые попытки не удаляются. Прямую запись браузерных ролей в попытки/оценки
миграция запрещает: результаты проверки и автора оценки определяет API.

Учитель выбирает класс → «Прогресс и оценки» → ученика. Журнал показывает все
12 тем курса, прочитанные шаги, результат проверки знаний, отправленные попытки,
историю решений этого класса и общих упражнений курса. Решения чужих классов
и тестовые запуски учителей исключены. Текст решения и блоки открываются только
для чтения. Новые попытки машины содержат снимок карты для пошагового просмотра;
для электроники доступны схема, соединения, код и блоки.

Оценка 0–10 и комментарий сохраняются отдельно для ученика, класса и раздела
курса (либо урока учителя). Оценка ручная, не заменяет результат автопроверки;
повторное сохранение обновляет текущую оценку. Истории изменений оценок пока нет.
Ученик видит только свои оценки в «Моём классе».

Важно: процент относится к теории и тесту, практика показана отдельно. При
переходе в практику из темы новая попытка привязывается к этой теме; общие
тренировки и старые попытки остаются в общей истории и не засчитываются за новые задания.
Для каждой из 12 тем есть отдельная практика: 10 маршрутов машины и 2 упражнения
электроники (5.1 — световой сигнал, 5.2 — ночник с датчиком). В темах про циклы и
условия проверяется их реальное выполнение; тема 4.2 проверяет одну программу на
двух картах, 6.2 предлагает исправить ошибочный поворот. Свободная практика и
упражнение с кнопкой остаются доступны отдельно. Чтение пользовательских уроков учителя
пока не отслеживается — для них показаны результаты привязанных заданий.
Несохранённые черновики и локальные гостевые результаты учителю недоступны.
Для старых попыток, где блоки и карта не записывались, доступен только сохранённый
код и прежний результат; они не восстанавливаются приблизительно.

Перед деплоем этой версии выполните в Supabase → SQL Editor файл
[202610140003_course_practice.sql](supabase/migrations/202610140003_course_practice.sql)
после миграции журнала `202610140002_teacher_review.sql`. Он добавляет 10 встроенных
заданий для сохранения решений без удаления данных. Проверки и привязка к теме
определяются сервером, а не полями браузера.

Для импорта встроенного курса и локального деморежима рядом с каждой исходной презентацией `Презентация.pptx` нужен заранее экспортированный `Презентация.pdf`. API не конвертирует презентации при запросе. Маршрут `/api/materials/preview?path=…` принимает точный путь из каталога либо идентификатор загруженного материала, выданный API, и сохраняет ограничения доступа аудитории и класса.

При обновлении PPTX экспортируйте все слайды в PDF через PowerPoint или LibreOffice и обновите соседнюю PDF-копию. `npm run check:previews` проверяет наличие копий, количество слайдов и текстовый слой (для чтения архива PPTX нужна утилита `unzip`). Для визуальной проверки можно добавить `-- --render-dir /tmp/easycode-previews-qa`: появятся изображения страниц, контактные листы и отчёт. Рендеринг использует необязательную зависимость PDF.js `@napi-rs/canvas`; если npm был запущен с `--omit=optional`, потребуется установить её отдельно. Проверка не заменяет визуальное сравнение с исходной презентацией.

### Обновлённые презентации

Презентации тем 2.1, 2.2, 4.1, 4.2, 5.1, 5.2, 6.1 и 6.2 обновлены из файлов
пользователя от 14 октября 2026 года: по 12 слайдов в каждой. Номера файлов
3, 4, 7, 8, 9, 10, 11, 12 соответствуют этим темам по порядку. Разделы 1 и 3
не менялись. Исходники состоят из изображений: PDF сохраняет расположение и
оформление, но не содержит выделяемого текстового слоя. Проверка допускает
такой формат только для файлов с совпадающими SHA-256 из
`content/materials/presentation-sources.json` и требует изображение на каждой странице.
В самих исходниках замечены искажения текста: тема 5.1, слайд 10; тема 6.2, слайд 7.
Содержимое этих слайдов не редактировалось.

Для повторной загрузки только этих презентаций (без конспектов и других тем):

```bash
npm run materials:check -- --topics 2.1,2.2,4.1,4.2,5.1,5.2,6.1,6.2
npm run materials:upload -- --topics 2.1,2.2,4.1,4.2,5.1,5.2,6.1,6.2
```

Загрузка обновляет ссылки в `learning_materials`; старые объекты Storage
не удаляются. Предыдущие локальные версии также доступны в истории Git.

### Сохранение прогресса

Для облачного хранения примените после начальной схемы [миграцию прогресса](supabase/migrations/202610070001_lesson_progress.sql) в SQL Editor своего проекта Supabase. Она добавляет таблицу и серверную функцию; существующие классы и решения не удаляются. Через браузер ученик может читать только свой прогресс, а результаты проверки записывает API. Миграция не применяется автоматически при запуске приложения.

Гостевой прогресс хранится в `localStorage` этого браузера отдельно от аккаунтов. После входа загружается прогресс соответствующего аккаунта; гостевые баллы не переносятся в облако. Если миграция ещё не применена или серверное сохранение недоступно, интерфейс явно сообщает о локальном сохранении. Очистка данных браузера удаляет такие локальные отметки. Деморежим хранит серверный прогресс только до перезапуска API.

## Проверки и сборка

```sh
npm run typecheck
npm test
npm run build
```

Сборка включает `npm run check:server-runtime`: отдельную компиляцию API в
NodeNext-модули и запуск в обычном Node.js без сборщика. Проверка использует
тестовые настройки без обращений к Supabase и выявляет ошибки импорта JSON,
которые Vite и тестовый раннер могут скрывать. Для JSON-импортов серверного и
общего кода необходим атрибут `with { type: "json" }`.

`npm start` запускает собранный API. Статический клиент из `dist/` размещается отдельно либо обслуживается обратным прокси; запуск API сам по себе не публикует веб-приложение.

Для прямого открытия `/login`, `/register`, `/learn` и `/learn/topic/:id` на статическом хостинге настройте SPA fallback на `index.html`; `/api` при этом должен оставаться маршрутом серверного API.

Сборка API находится в `build/server/index.js`. Запускайте `npm start` из корня репозитория. В деморежиме сервер читает исходные материалы и PDF-копии из `content/materials/` относительно рабочей папки. В Supabase-режиме нужен только каталог, а файлы загружаются из приватного Storage. Напрямую публиковать папку материалов как статические файлы нельзя.

### Деплой сайта и API на Vercel

В репозитории есть `vercel.json` и серверная функция `api/index.ts`. Vercel
собирает сайт в `dist/`, а `/api/*` направляет в существующий Fastify API.
Функция не запускает `listen()` и не требует отдельного сервера на порту 3001.
В серверный пакет включается только каталог `content/materials/catalog.json`;
сами документы хранятся в Supabase Storage. Сначала выполните подключение Storage
и импорт материалов по инструкции выше. Проверки роли и доступа сохраняются.

1. Отправьте изменения, включая `api/`, `vercel.json` и учебные материалы, в
   Git-репозиторий, подключённый к Vercel. Redeploy старого коммита новые файлы не добавит.
2. Root Directory — корень проекта, Framework Preset — **Vite**,
   Build Command — `npm run build`, Output Directory — `dist`.
3. В Environment Variables для **Production** задайте:

   | Переменная | Тип | Значение |
   |---|---|---|
   | `DEMO_MODE` | Config | `false` |
   | `FRONTEND_ORIGIN` | Config | `https://easy-code-nu.vercel.app` (или ваш домен) |
   | `VITE_SUPABASE_URL` | Config | URL проекта Supabase |
   | `VITE_SUPABASE_ANON_KEY` | Config | Публичный anon-ключ этого проекта |
   | `SUPABASE_URL` | Config | Тот же URL Supabase |
   | `SUPABASE_SERVICE_ROLE_KEY` | Secret | Сервисный ключ; без префикса `VITE_` |

   Необязательные AI-настройки остаются серверными: `OPENAI_API_KEY` — Secret,
   `OPENAI_MODEL` — Config. `HOST`, `PORT` и `EASYCODE_API_PROXY` на Vercel не нужны.
   Не загружайте `.env` в Git. Preview должен использовать отдельную тестовую базу
   и свой точный `FRONTEND_ORIGIN`; произвольные домены `*.vercel.app` не разрешаются.
4. В Supabase Authentication → URL Configuration укажите production Site URL
   и разрешённые redirect URL для используемого сценария подтверждения входа.
   Убедитесь, что SQL-миграции проекта применены к этой базе.
5. Запустите новый production deployment. Проверьте `/api/health`: должен вернуться
   JSON с `"mode":"supabase"`, а не 404 или HTML. Это проверка запуска API,
   не соединения с базой: после неё проверьте вход, создание класса и сохранение прогресса.

При 503 смотрите Vercel Runtime Logs и проверьте серверные переменные, `DEMO_MODE`
и наличие `content/materials/catalog.json` в поставке. После изменения ENV нужен
новый deployment. Лимитер запросов работает в памяти одного экземпляра функции;
для единого глобального лимита при масштабировании нужен общий внешний store.

### Проверки в браузере

Сначала запустите `npm run dev` с `DEMO_MODE=true`. Во втором терминале:

```sh
npm run test:e2e
```

Проверки Playwright используют локально установленный Chrome. По умолчанию ожидается путь macOS `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`. Для другого расположения укажите исполняемый файл:

```sh
CHROME_PATH="/абсолютный/путь/к/chrome" npm run test:e2e
```

Снимки и диагностические материалы создаются в `test-results/`; папка исключена из Git. Проверки работают с локальными демонстрационными данными, а не с настоящими аккаунтами Supabase.

Автотесты проверяют код проекта, но не заменяют проверку реального Supabase, почтовой авторизации, политики доступа, AI-ответов и облачного развёртывания.

## Языки платформы

В шапке сайта, учебного кабинета и формы входа доступны Русский, Қазақша и English.
Выбор хранится в браузере (`easycode:language`) и применяется без выхода из аккаунта,
перезагрузки страницы или сброса ответов, прогресса и программы. Предпочтение не
синхронизируется через Supabase; миграции для него не нужны.

Переведены интерфейс, встроенные задания, учебные блоки, сообщения симуляторов и
все 12 веб-уроков (адаптированные английская и казахская версии). Идентификаторы
уроков, шагов и вариантов ответов одинаковы на всех языках. Оценивание по-прежнему
выполняется сервером; переводы объяснений теста выдаются только после проверки.
API подсказок принимает необязательный `language: "ru" | "kk" | "en"` (по умолчанию `ru`).

Имена, введённый код, материалы учителя и прикреплённые DOCX/PPTX/PDF остаются в
исходном языке. Это не автоматический перевод пользовательского контента.

Словари интерфейса: `shared/locales/`; адаптации веб-уроков:
`shared/locales/lessons-en.json` и `lessons-kk.json`; закрытые до проверки объяснения:
`server/locales/lesson-feedback.json`. Автотесты проверяют полноту словарей,
сохранение идентификаторов и состояние форм при переключении.
