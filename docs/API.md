# API первой версии

Базовый путь — `/api`. Локальный сервер: `http://localhost:3001`. Запросы с JSON отправляются с `Content-Type: application/json`. В Supabase-режиме файловые маршруты возвращают JSON `{ "url": "…" }` с временной ссылкой на приватный Storage; в локальном деморежиме — непосредственно документ или PDF.

## Авторизация

`GET /api/health` открыт. `GET /api/catalog` без токена возвращает общедоступные сведения о курсе и только ученические материалы. Чтение `GET /api/lessons/:id` и проверка `POST /api/lessons/:id/check` также доступны гостю, но гостевой результат не сохраняется. Скачивание файлов, чтение/изменение прогресса и остальные маршруты требуют пользовательской сессии либо локального деморежима.

Конспекты добавляются в каталог только для подтверждённой роли учителя. Если токен передан, но недействителен, каталог тоже отвечает `401`, а не игнорирует ошибку авторизации. Ответ каталога имеет `Cache-Control: private, no-store`, чтобы сведения преподавателя не попали в общий кэш.

В режиме Supabase:

```http
Authorization: Bearer <access_token текущей сессии Supabase>
```

API проверяет JWT через Supabase и читает защищённый профиль. Сервисный ключ базы не передаётся браузером. Выбор роли при входе и последующее изменение метаданных не меняют права сохранённого аккаунта.

Регистрация и вход выполняются через Supabase Auth, не через новый маршрут платформы. При регистрации клиент передаёт `signUp({ email, password, options: { data: { name, role } } })`, где `role` равен `student` или `teacher`. Требуется миграция `202610070002_signup_roles.sql`: только при вставке нового `auth.users` она создаёт защищённый профиль с выбранной допустимой ролью; неизвестная/отсутствующая роль становится учеником. Обновление `user_metadata.role` после регистрации не запускает назначение роли.

После входа клиент читает `GET /api/me` и сравнивает выбранный кабинет с сохранённым `role`. Поле формы не отправляется в API для повышения прав, маршрута самостоятельной смены роли нет. Существующие профили новая миграция не изменяет. Учительская регистрация открыта, но даёт только права на собственные классы, разделы и задания, а также доступ к общим учительским материалам; административных прав она не даёт.

В локальном режиме `DEMO_MODE=true` используется заголовок:

```http
x-demo-role: teacher
```

Допустимы `teacher` и `student`; роль по умолчанию — ученик. Этот заголовок предназначен только для локального тестирования и не заменяет токен в режиме Supabase. Данные деморежима сбрасываются при перезапуске API.

## Маршруты

| Метод и путь | Назначение | Доступ |
| --- | --- | --- |
| `GET /health` | Режим работы и готовность настройки AI | Без входа |
| `GET /me` | Профиль текущего пользователя | Пользователь |
| `GET /catalog` | Каталог курса с материалами, отфильтрованными по роли | Общие сведения без входа; конспекты — подтверждённому учителю |
| `GET /lessons/:id` | Урок, шаги и вопросы без ключа ответов | Без входа |
| `GET /lesson-progress` | Прогресс текущего профиля | Пользователь, только собственный прогресс |
| `POST /lessons/:id/progress` | Отметить прочитанным существующий шаг | Пользователь, только собственный прогресс |
| `POST /lessons/:id/check` | Проверить полный набор ответов на сервере | Без входа; сохраняется только при наличии сессии |
| `GET /materials?path=…` | Скачать разрешённый файл курса или класса | Пользователь, по аудитории и членству в классе |
| `GET /materials/preview?path=…` | Открыть подготовленный PDF презентации | Пользователь, по аудитории исходной презентации |
| `GET /classes` | Доступные классы | Свои классы учителя или членство ученика |
| `POST /classes` | Создать класс и код присоединения | Учитель |
| `POST /classes/join` | Присоединиться по коду | Ученик |
| `GET /sections?classId=…` | Получить разделы указанного класса | Владелец класса / участник |
| `POST /sections` | Создать раздел с теорией | Владелец класса |
| `GET /class-materials?classId=…` | Опубликованные материалы класса | Владелец класса / участник |
| `POST /class-materials/uploads` | Подготовить прямую загрузку в Storage | Владелец класса |
| `POST /class-materials/:id/complete` | Проверить и опубликовать загруженные файлы | Автор материала — владелец класса |
| `GET /tasks?classId=…` | Получить встроенную практику и задания указанного класса | Владелец класса / участник; без `classId` — только встроенная практика |
| `POST /tasks` | Создать практическое задание | Владелец класса |
| `GET /submissions?classId=…` | Получить до 200 последних доступных попыток | Свои попытки; учитель с `classId` видит попытки своего класса |
| `POST /submissions` | Отправить решение на серверную проверку | Пользователь с доступом к заданию |
| `POST /electronics-submissions` | Проверить и сохранить схему, код и блоки | Пользователь |
| `GET /classes/:classId/students` | Имена и ID участников-учеников | Владелец класса |
| `GET /classes/:classId/students/:studentId/progress` | Теория, сводка всех попыток и оценки ученика | Владелец класса, ученик должен состоять в классе |
| `GET /classes/:classId/students/:studentId/attempts/:attemptId?kind=robot` | Полное решение (`kind=robot` или `electronics`) | Владелец класса, без чужих классов и тестов учителя |
| `POST /classes/:classId/students/:studentId/grades` | Поставить или обновить оценку за раздел | Владелец класса |
| `GET /classes/:classId/my-grades` | Оценки текущего аккаунта в классе | Участник класса |
| `POST /hints` | Получить локальную или AI-подсказку | Пользователь с доступом к заданию |

Доступ проверяется сервером для каждого запроса. Подстановка чужого `classId`, `sectionId` или `taskId` не должна открывать данные.

`classId` обязателен для списка разделов; для списков заданий и попыток он необязателен. Без `classId` список попыток ограничен текущим пользователем, в том числе для учителя. При запросе учителем журнала класса его тестовые запуски исключаются: возвращаются только ученические попытки с `is_test=false`. Идентификаторы классов и разделов имеют формат UUID.

## Хранение и загрузка материалов

Требуется миграция `supabase/migrations/202610140001_material_storage.sql`.
Метаданные находятся в `learning_materials`, файлы — в приватном bucket
`easycode-materials`. Браузер не имеет прямого доступа к таблице или списку объектов.
Существующие материалы импортируются командой `npm run materials:upload`.

`GET /class-materials?classId=…` возвращает `{ "materials": [...] }`: только записи
со статусом `ready`, доступные текущему профилю. Публичное описание содержит
`id`, `title`, `path`, `type`, `audience`, `section_id`, `filename`, `size_bytes`,
но не внутренние пути Storage. В деморежиме список пуст, загрузка недоступна.

Подготовка загрузки:

```http
POST /api/class-materials/uploads
```

```json
{
  "classId": "UUID своего класса",
  "sectionId": null,
  "title": "Наши алгоритмы",
  "filename": "algorithms.pptx",
  "extension": "pptx",
  "size": 12345,
  "previewSize": 54321
}
```

Допустимы `pdf`, `pptx`, `docx`; каждый файл — от 1 байта до 20 МБ.
`previewSize` обязателен только для PPTX: нужен отдельно экспортированный PDF.
PDF сам служит своей копией для просмотра; DOCX только скачивается.
`sectionId`, если указан, должен принадлежать этому же классу.

Ответ: `{ "id": "…", "bucket": "easycode-materials", "original":
{ "path": "…", "token": "…", "contentType": "…" }, "preview": null }`.
Для PPTX `preview` содержит такой же объект для PDF. Пути генерирует сервер.
Браузер вызывает Storage `uploadToSignedUrl` для каждого файла с `upsert: false`,
затем `POST /class-materials/:id/complete` с телом `{}`. Сервер сверяет реальные
размеры и сигнатуры, после чего возвращает `{ "material": ... }`. Повторное
подтверждение опубликованной записи безопасно. Это не антивирусная проверка.
Незавершённые записи остаются `pending` и ученикам не видны.

Пути встроенного курса совпадают с каталогом; для загруженного материала клиент
использует выданный API `cloud/<id>/<filename>`. Файловые маршруты проверяют сессию,
роль и доступ к классу перед выдачей ссылки на 60 секунд. Ответы имеют
`Cache-Control: private, no-store`. Клиент скачивает файл по подписанной ссылке
без заголовка Authorization аккаунта и без cookies; ссылка сама временно даёт
доступ к файлу, поэтому её не следует публиковать или сохранять в логах.
Автоматической конвертации PPTX, редактирования и удаления материалов пока нет.

## Контракты запросов

### Состояние сервера

```json
{
  "mode": "demo",
  "aiConfigured": false
}
```

`aiConfigured` показывает наличие настройки, а не успешный тест внешней модели или доступный баланс аккаунта.

`GET /me` возвращает профиль без обёртки: `{ "id": "…", "name": "…", "role": "student" }`. `GET /catalog` возвращает `{ "course": ..., "sections": [...] }`.

### Уроки и прогресс

Идентификаторы уроков совпадают с темами: `1.1`–`6.2`. `GET /api/lessons/1.1` возвращает `{ "lesson": ... }` с четырьмя шагами и тремя вопросами. `correctOptionId` и объяснения правильных ответов не передаются в определении урока. Исходники с ключами ответов импортирует только сервер. Темы каталога с готовым уроком дополнены полем `lesson: { stepIds: string[], durationMinutes: number }`.

```http
POST /api/lessons/1.1/progress
```

```json
{ "stepId": "concept" }
```

Ответ: `{ "progress": { "lessonId": "1.1", "completedStepIds": ["concept"], "bestScore": null, "quizPassed": false, "completedAt": null, "updatedAt": "…" } }`. Повторная отметка шага безопасна и не создаёт дубликат. Нельзя передать чужой профиль, оценку или несуществующий шаг. `GET /api/lesson-progress` возвращает `{ "progress": [...] }` только текущего пользователя; учитель не получает здесь прогресс других учеников.

```http
POST /api/lessons/1.1/check
```

```json
{ "answers": { "1.1-q1": "a", "1.1-q2": "b", "1.1-q3": "c" } }
```

Это пример формата, а не ключ правильных ответов. Требуются ответы ровно на все вопросы и существующие варианты. Сервер возвращает `{ "result": { "score": 2, "total": 3, "passed": false, "feedback": [{ "questionId": "1.1-q1", "correct": false, "explanation": "…" }] }, "progress": ... }`; `feedback` содержит каждый вопрос. `score` и `bestScore` — количество верных ответов, не проценты. Пройти проверку можно только с тремя верными ответами.

Прочитанные шаги, лучший результат и успешная проверка не сбрасываются при повторной попытке. `completedAt` устанавливается один раз, только когда прочитаны все шаги и проверка пройдена. В Supabase изменения атомарно объединяет RPC `merge_lesson_progress`; выполнить её может только `service_role`, а таблица `lesson_progress` разрешает браузеру лишь чтение собственных строк через RLS.

Для гостя ответ всегда содержит `progress: null` и ничего не сохраняет. При недоступности облачного сохранения проверка всё равно возвращает вычисленный `result`, `progress: null` и явное `warning`. Чтение/изменение прогресса в таком случае возвращает `503`; если отсутствует новая схема, сообщение предлагает применить `supabase/migrations/202610070001_lesson_progress.sql`. Никакого автоматического переключения облачного прогресса в фиктивное локальное сохранение нет. Деморежим явно хранит прогресс в памяти процесса и сбрасывает его при перезапуске.

### Классы

Создание:

```http
POST /api/classes
```

```json
{ "name": "5 А — алгоритмы" }
```

Ответ содержит `{ "class": ... }`; список классов — `{ "classes": [...] }`. Созданный класс принадлежит текущему учителю. Каждый класс в списке содержит `member_count` — фактическое число участников, а не демонстрационную заглушку. Код `join_code` показывается учителю; в ответах ученику он пустой.

Присоединение:

```http
POST /api/classes/join
```

```json
{ "code": "КОД-КЛАССА" }
```

Ответ: `{ "class": ... }`. Код используется для присоединения, но не является токеном авторизации или способом доступа к попыткам других учеников.

### Разделы

```http
POST /api/sections
```

```json
{
  "classId": "идентификатор класса",
  "title": "Наши первые алгоритмы",
  "theory": "Алгоритм — это понятная исполнителю последовательность действий."
}
```

Ответ: `{ "section": ... }`; список — `{ "sections": [...] }`. API проверяет владение классом.

### Задания

```http
POST /api/tasks
```

Поля тела:

| Поле | Значение |
| --- | --- |
| `classId` | Идентификатор собственного класса |
| `sectionId` | Необязательный идентификатор раздела того же класса |
| `title` | Название |
| `description` | Инструкция ученику |
| `difficulty` | `easy`, `medium` или `hard` |
| `world` | Клеточное поле, старт, цель и препятствия по типам общего движка |

Ответ: `{ "task": ... }`; список — `{ "tasks": [...] }`. Встроенное стартовое задание имеет идентификатор `intro-route` и не привязано к классу.

Формат `world` определяется типами в `shared/` и проверяется сервером. Нельзя переносить эту проверку только в форму учителя: запрос может быть отправлен без интерфейса.

В текущем интерфейсе учитель создаёт задания на подготовленной карте. Произвольную карту можно передать через API, но визуальный редактор стартовой позиции, цели и препятствий ещё не реализован.

Пример поля:

```json
{
  "width": 8,
  "height": 6,
  "start": { "x": 1, "y": 4, "direction": "east" },
  "goal": { "x": 6, "y": 1 },
  "obstacles": [{ "x": 4, "y": 3 }, { "x": 3, "y": 2 }]
}
```

Координаты начинаются с нуля; `x` увеличивается вправо, `y` — вниз. Размер каждой стороны — от 2 до 32 клеток. Направления: `east`, `south`, `west`, `north`. API принимает до 512 препятствий. Старт, цель и препятствия должны находиться внутри поля; препятствия не могут занимать старт или цель.

### Отправка решения

```http
POST /api/submissions
```

```json
{
  "taskId": "intro-route",
  "code": "robot.forward(1)",
  "language": "kk"
}
```

Тело не содержит доверенной оценки, клиентской цели или траектории. API загружает условия по `taskId`, проверяет доступ, разбирает разрешённый код и выполняет серверную симуляцию. Ответ содержит `{ "submission": ..., "result": ... }`; список попыток — `{ "submissions": [...] }`.

Дополнительные поля отправки: `editorMode: "code" | "blocks"` (по умолчанию `code`),
`blocksState` (JSON Blockly, только для режима blocks), необязательный `lessonId`.
Сервер нормализует разрешённые типы блоков, ограничивает размер/количество/вложенность,
заново генерирует код и отклоняет несовпадение с переданным кодом. В режиме `code`
передавать блоки нельзя. Снимок задания формируется сервером, а не браузером.
Для 10 встроенных практик используются ID `course-1-1` … `course-4-2`,
`course-6-1`, `course-6-2`. Их `lesson_id` определяется сервером; необязательный
`lessonId` должен совпадать с ним. У `intro-route` и заданий учителя передавать
`lessonId` нельзя. Результат курса содержит `checks: [{ label, passed }]`:
проверяется цель, реальные действия внутри циклов/условий и лимит шагов (6.2).
Тема 4.2 проверяется на обеих картах. Снимок содержит `courseTask` с условиями и
вариантами карт для просмотра учителем. Перед сохранением нужны записи заданий
из миграции `202610140003_course_practice.sql`.

`POST /electronics-submissions`: `{ exercise: "blink" | "button" | "night", code,
editorMode, blocksState?, circuit: { parts: [...], wires: [...] }, lessonId?: "5.1" | "5.2" }`.
Тема 5.1 разрешает только `blink`, тема 5.2 — только `night`; без темы доступны
все три упражнения, но они не засчитываются за тему в журнале курса.
Сервер проверяет структуру схемы и выполняет тот же детерминированный симулятор;
это не ручная оценка и не доказательство безопасности физической схемы.

Журнал возвращает `{ progress, attempts, grades, lessons }`. `attempts` содержит
только ID, тип среды, задание, привязку к теме, результат и время, без тяжёлых
снимков/кода. Все страницы БД читаются, в отличие от старого списка последних
200 попыток. Полное решение запрашивается отдельно и повторно проверяет доступ.
Теория общая для курса, но задания других классов не раскрываются. Ключей ответов
в метаданных тем нет. Ответы с персональными данными не кэшируются.

Оценка: `{ "sectionKey": "course:1", "score": 8, "comment": "Проверь цикл" }`.
Допустимы `course:1`–`course:6` и `custom:<UUID урока этого класса>`, целый балл
0–10, комментарий до 2000 символов. Сервер берёт автора из проверенного профиля,
проверяет владельца класса и членство ученика. Повторная запись обновляет текущую
оценку по `(class_id, student_id, section_key)`; ответ `{ "grade": ... }`.
Оценки и схема хранения требуют `202610140002_teacher_review.sql`.

`result` содержит `success`, `message`, `steps` и `frames`. Каждый кадр — `{ "x": 1, "y": 4, "direction": "east", "command": "Старт" }`. `steps` считает пройденные клетки, а не повороты. Успех означает, что программа завершилась на целевой клетке без ошибки. Ошибка учебного кода является результатом неуспешной попытки, а не аварией HTTP-сервера.

`submission` содержит `id`, `task_id`, `class_id`, `student_id`, `is_test`, `code`, `success`, `steps`, `feedback` и `created_at`. Значение `is_test` назначается сервером: `true` для запуска учителем, `false` для ученика. Клиент не выбирает этот признак. Учитель видит собственные тестовые запуски в личном списке без `classId`, но они не смешиваются с ученическими результатами в журнале класса.

Blockly отправляет сгенерированный учебный текст тому же обработчику. Сериализация рабочей области блоков для восстановления черновика — отдельная задача и не является доказательством правильности решения.

### Подсказка

```http
POST /api/hints
```

```json
{
  "taskId": "intro-route",
  "code": "robot.forward(1)"
}
```

`taskId` необязателен; без него используется `intro-route`. `language` — необязательный язык подсказки: `ru` (по умолчанию), `kk` или `en`. Неизвестное значение отклоняется. Язык применяется и к локальной подсказке, и к инструкции AI; права доступа и проверка кода не меняются. Пример ответа для русского языка:

```json
{
  "hint": "Подумай, сколько клеток осталось до цели.",
  "source": "local"
}
```

`source` равен `local` или `openai`. При пустом ключе или модели используется локальная подсказка. Вызов модели производится только сервером; запрос использует `store: false`. Сервер передаёт описание задания, код и результат движка, не добавляя профиль, имя или почту аккаунта. Пользователь может сам написать личные сведения в коде или описании, поэтому это не гарантия полного отсутствия персональных данных в запросе. `store: false` также не означает отсутствия всех журналов у провайдера; перед пилотом отдельно проверяется принятая политика обработки данных.

При ошибке AI возвращается локальная подсказка с необязательным полем `notice`.

### Материалы

```http
GET /api/materials?path=section-01%2Ftopic-01%2FПрезентация.pptx
```

Передавайте значение `path` через `encodeURIComponent`. Допустимы только точные пути, зарегистрированные в каталоге. Ссылка на файл с аудиторией `teacher` требует роли учителя. Перебор `../`, абсолютный путь или неизвестное имя не должны приводить к чтению файлов вне каталога. Этот маршрут продолжает выдавать оригинал с `Content-Disposition: attachment`.

Для просмотра презентации внутри сайта:

```http
GET /api/materials/preview?path=section-01%2Ftopic-01%2FПрезентация.pptx
Authorization: Bearer <access_token>
```

В `path` передаётся путь **исходной PPTX**, а не PDF. Сервер принимает только материал каталога с типом `presentation` и расширением `.pptx`, проверяет аудиторию и читает заранее экспортированный файл с тем же именем и расширением `.pdf` в той же папке. Произвольные PDF-пути, внешние URL и дополнительные параметры запроса не принимаются. Маршрут не выполняет конвертацию при запросе и не отправляет документы внешнему просмотрщику.

Успешный ответ: `200`, `Content-Type: application/pdf`, `Content-Disposition: inline; filename*=UTF-8''…`, `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`. Без сессии — `401`; для закрытого учительского материала у ученика — `403`; неизвестный материал, неподдерживаемый тип или ещё не подготовленный PDF — `404`. При отсутствии PDF сообщение предлагает скачать исходный PPTX. PDF хранится рядом с оригиналом в приватной папке `content/materials/`, не в `public/`, и должен входить в поставку сервера.

Клиент сначала получает PDF авторизованным `fetch`, затем показывает его внутри сайта. Прямая ссылка в `iframe` сама по себе не передаёт заголовок Bearer. PDF — статичная копия слайдов: анимации, переходы и интерактивное содержимое PPTX в ней не воспроизводятся; оригинал остаётся доступен для скачивания.

План разделов доступен учителю по пути `course-plan/План разделов.docx`. Сейчас файлы читаются из `content/materials/`. Приватный бакет Supabase `course-materials` подготовлен миграцией, но загрузка и выдача файлов через него ещё не подключены. Его ограничительная политика запрещает прямые операции ролям `anon` и `authenticated`, в том числе при наличии других разрешающих политик Storage; будущий файловый API должен проверять права до выдачи временной ссылки.

## Учебный язык

| Запись | Значение |
| --- | --- |
| `robot.forward(N)` | Проехать вперёд на `N` клеток |
| `robot.backward(N)` | Проехать назад на `N` клеток без изменения направления |
| `robot.turn_left()` | Повернуться влево на 90° |
| `robot.turn_right()` | Повернуться вправо на 90° |
| `robot.stop()` | Закончить выполнение программы |
| `for i in range(N):` | Повторить вложенный блок `N` раз |
| `if robot.obstacle_ahead():` | Выполнить ветку, если впереди препятствие или граница поля |
| `else:` | Альтернативная ветка непосредственно после `if` |
| `pass` | Пустое действие |
| `# комментарий` | Неисполняемый комментарий |

`N` — целое число от 0 до 100. Тела циклов и условий выделяются пробелами; табуляция отклоняется. Переменные, выражения и произвольные вызовы не поддерживаются; имя счётчика цикла не делает его доступной переменной.

API принимает до 12 000 символов кода. Движок дополнительно ограничивает программу 400 строками, 400 командами в структуре, восемью уровнями вложенности, 1 000 операциями исполнения и 500 перемещениями. Итерации циклов тоже расходуют бюджет операций.

## Ошибки и ограничения запросов

Ошибки API имеют форму `{ "error": "Понятное сообщение" }`; при проверке полей может добавляться `details` — массив пояснений. Успешные JSON-операции первой версии возвращают HTTP 200.

| Статус | Причина |
| --- | --- |
| `400` | Некорректный формат полей или неизвестная демороль |
| `401` | Нет действительной сессии Supabase |
| `403` | Не хватает прав, запрещённый источник или попытка удалённого доступа к деморежиму |
| `404` | Класс, код, задание или материал не найден |
| `413` | Тело запроса больше допустимого размера |
| `429` | Превышен лимит запросов |
| `500` | Ошибка сервиса или конфигурации без раскрытия внутренних деталей |
| `503` | Хранилище прогресса недоступно либо не применена его миграция |

Размер тела — до 64 КиБ. До проверки сессии действует защитный лимит 500 запросов в минуту на IP. После проверки сессии общий лимит составляет 100 запросов в минуту на профиль (в локальном деморежиме — 500); присоединение к классу — 8, подсказки — 6 на профиль. Неавторизованные публичные запросы учитываются по IP. Ответ `429` содержит русское пояснение и заголовок `Retry-After` в секундах.

Квоты хранятся в памяти одного процесса. `trustProxy` не включён: произвольный `X-Forwarded-For` не меняет IP и не обходит ограничение. За обратным прокси предварительная IP-квота будет общей для его запросов, пока при развёртывании не настроены точные доверенные IP/CIDR прокси. Нельзя просто доверять заголовку от любого клиента. Для нескольких экземпляров API потребуется общее хранилище квот, например Redis. Эти настройки проверяются до школьного пилота.

## Ограничения контракта

- Текстовый язык ограничен командами учебного движка; это не произвольный Python.
- Сервер ограничивает размер входа и вычисления; бесконечное исполнение не допускается.
- Демоидентификаторы и данные не следует переносить в рабочую базу как реальные аккаунты.
- AI недоступность не должна блокировать самостоятельное выполнение практики.
- Загрузка файлов поддерживается через приватный Supabase Storage (см. ниже); полноценное редактирование и удаление контента, экспорт журналов и управление школьной организацией пока не реализованы.
- Документ описывает контракт локальной реализации; облачная интеграция и поведение RLS требуют отдельной проверки на реальном Supabase.
