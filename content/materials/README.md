В этой папке хранятся материалы курса. Предоставленные автором оригиналы сохранены без изменений. Для тем 3.1–6.2 добавлены новые презентации на основе соответствующих веб-уроков.

Полный план содержит 6 разделов и 12 тем. После каждого раздела предусмотрена практическая работа с заданиями начального, среднего и высокого уровней сложности.

Файл `catalog.json` содержит структуру курса, аудиторию каждого материала и относительные пути к файлам. В дальнейшем его можно использовать для первоначального наполнения базы Supabase.

## Правила отображения

- Презентации доступны ученикам и учителям.
- Конспекты уроков доступны только учителям.
- Черновые и отсутствующие материалы не публикуются ученикам.
- Практические задания будут храниться отдельно от теоретических материалов и связываться с соответствующей темой.

## PDF для просмотра на сайте

Рядом со всеми 12 PPTX лежат одноимённые PDF-копии. Они содержат статичные слайды; анимации и переходы не воспроизводятся. PDF выдаёт защищённый API с правами исходной презентации; не переносите эти файлы в `public/`. Материал типа `presentation` в каталоге автоматически получает кнопку просмотра на странице урока. Изменения базы данных не требуются.

### Новые презентации разделов 3–6

Каждая из восьми презентаций содержит 7 слайдов: обложку, четыре объяснения с примерами, практическое задание и самопроверку. PPTX содержит редактируемый текст. PDF использует ту же разбивку строк и геометрию, со встроенными кириллическими шрифтами. Раздел 5 явно описывает бумажную модель: симулятор электроники пока не реализован. Материалы не содержат ключей серверных мини-проверок.

Содержание: `content/presentations/sections-03-06.mjs`, источник и практические задания: `content/lessons/index.ts`. Генератор: `scripts/build-course-presentations.mjs` (Node.js 24). Зависимости для подготовки файлов не входят в зависимости платформы.

Для повторного создания установите `pptxgenjs@4.0.1` и `pdfkit@0.17.2` в отдельную временную папку, затем выполните:

```sh
node scripts/build-course-presentations.mjs --tools-dir /private/tmp/easycode-authoring --output-dir /private/tmp/easycode-new-decks
```

Генератор ожидает шрифты Arial, Arial Bold и Courier New в `/System/Library/Fonts/Supplemental`. Для другой системы задайте `--font-dir` с этими TTF-файлами. Он не перезаписывает существующие выходные файлы. После проверки замените только соответствующие новые PPTX/PDF в `section-03`–`section-06`, запустите `npm run check:previews -- --render-dir /private/tmp/easycode-preview-qa` и просмотрите PNG всех слайдов.

### Предоставленные презентации разделов 1–2

Оригиналы PPTX не изменены. По согласованию с автором в браузерных копиях смысловые emoji заменены словами: например, «Когда кликнут по флажку», а на поле робота — «Робот» и «Цель». Декоративные значки, повторяющие соседнюю подпись, убраны. Это предотвращает пустые символы и неверную подстановку emoji в текстовой версии слайдов.

При обновлении материала сначала создайте временные совместимые PPTX-копии из корня проекта:

```sh
python3 scripts/prepare-preview-copies.py --out-dir /private/tmp/easycode-preview-copies
```

Скрипт читает каталог, изменяет согласованные текстовые фрагменты и служебную запись пространства имён, сверяет неизменность остальных XML-узлов и SHA256 оригиналов. Для размещения слов в клетках тема 1.2, слайд 9 использует «Цель» размером 20 пт вместо 24 пт и «Робот» размером 14 пт вместо 18 пт; в теме 2.1, слайд 10 добавлен перенос поясняющей фразы. Гарнитуры, встроенные шрифты, изображения, геометрия и отношения между файлами остаются прежними. Файл `compatibility-report.json` перечисляет все замены и изменения кегля. Уже существующие выходные файлы не перезаписываются: для повторного запуска выберите новую временную папку. Неизвестные emoji требуют явного дополнения словаря, а не удаляются молча.

Откройте полученные копии `topic-1.1-browser.pptx` … `topic-2.2-browser.pptx` в PowerPoint (предпочтительно) или LibreOffice и экспортируйте **все слайды** каждой в PDF. Проверьте переносы текстовых замен, затем перенесите только PDF к соответствующему исходнику под именем `Презентация.pdf`. Шрифты, размеры слайдов и оригинальные PPTX менять не нужно. Запустите `npm run check:previews -- --render-dir /private/tmp/easycode-preview-qa` и просмотрите контактные листы и PNG всех страниц. Автоматическая проверка наличия текста не обнаруживает визуально пустой emoji-глиф.

Текущие копии экспортированы через LibreOffice 26.8. Для тем **1.2 и 2.2** скрипт также устраняет несовместимость: LibreOffice сообщал `source file could not be loaded` при наличии префикса `ns0` в `[Content_Types].xml`. Замена его на пространство имён по умолчанию решила проблему; содержимое этого служебного XML осталось эквивалентным. Изменение порядка или удаление встроенных шрифтов не понадобилось. Конвертация в другом приложении может отличаться по отображению, поэтому визуальная проверка обязательна.
